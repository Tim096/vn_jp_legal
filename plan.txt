# ビジネス実務法務検定 2級 學習網站 — 專案計畫

**你把題庫做到 95 分交付,她在實際念書時修掉最後 5%。**

這個前提讓專案從「內容工程」變成「資料管線 + 回饋迴路」。兩個關鍵決定:AI 只做轉換不做生成、以及回饋必須能在手機上一鍵完成。

## 2. AI 資料管線

### 核心原則:AI 只做轉換,不做生成

這是整條管線唯一真正重要的規則。

- ✅ 「把這段 HTML 裡的題目、選項、正解、解說抽成 JSON」→ 高可靠
- ❌ 「幫我補上這題的根拠条文」→ 會編
- ❌ 「這題解說太簡略,幫我擴充」→ 會編
- ❌ 「翻譯成中文再翻回日文潤飾」→ 會走味

**原文沒有的資訊一律留空。** 空欄位是誠實的,編出來的欄位是有毒的——而你看不懂日文,無法察覺。

### Stage 1|取得原始文字

一章一個檔,`raw/ch09.txt`。用什麼方式取得由你決定。

### Stage 2|AI 轉換

Prompt 骨架:

```
以下は日本の資格試験の問題ページのテキストです。
各問題を JSON 配列に変換してください。

厳守事項:
- 原文にない情報は絶対に補完しない。不明な項目は null にする
- 解説は原文の要約のみ。新たな法的説明を加えない
- 条文番号は原文に明記されているものだけを law_refs に入れる
- 判断に迷った問題は needs_review: true を立て、reason に理由を書く

出力スキーマ:
{ chapter, title, question, options[], answer[], explanation,
  law_refs[], tags[], needs_review, reason }

出力は JSON のみ。説明文は不要。
```

**一次丟 10–15 題,不要整章。** 長輸出的尾端品質會掉,而掉的地方你看不出來。

### Stage 3|機器驗證(不需要懂日文)

寫一支 `validate.mjs`,這些檢查全部與語言無關:

| 檢查 | 抓什麼錯 |
|---|---|
| JSON schema | 結構壞掉 |
| `answer` 索引落在 `options` 範圍內 | 最常見的轉換錯誤 |
| `options.length` 為 2 或 4–5 | 選項被截斷或黏在一起 |
| 必填欄位非空(`question` / `options` / `answer`) | 漏抽 |
| 重複偵測:`question` 正規化後前 40 字比對 | 兩來源重疊、AI 重複輸出 |
| `law_refs` 符合 `^[ぁ-ん一-龥]+\d+` | 幻覺條文的常見形狀 |
| 章節分布 sanity check | 某章只有 3 題 = 那章漏抽了 |
| `explanation` 長度離群值 | 過短 = 沒抽到;過長 = AI 自己加料 |

**這關能擋掉大部分結構性錯誤,而這正是你能獨立做的部分。**

### Stage 4|AI 反向校對

換一個 prompt、換一個 session,讓 AI 當批改者重讀一遍:

```
以下の問題データを校閲してください。修正はせず、疑問点のみ報告。
特に確認する点:
- 正解と解説の内容が矛盾していないか
- 条文番号と説明内容が対応しているか
- 法改正で古くなっている可能性がある記述
出力: [{ id, issue, severity: high|mid|low }]
```

高 severity 的直接標 `confidence: low` 送進 Sheets,讓她優先看。

### 那 5% 會集中在哪裡

不是隨機分布的。AI 在**轉換**上很穩,在**時效性**上不穩。所以請預期錯誤集中在近年法改正頻繁的領域:

**個人情報保護法、労働法制、デジタル関連法(ch05 / ch06)、独占禁止法、消費者関連法(ch04)。**

實務做法:這幾章的題目一律預設 `confidence: mid`,不管 AI 說多有把握。讓她從這幾章開始念,錯誤最早浮現。

## 3. 資料層:Google Sheets

前期由你灌入,後續當作可即時修改的線上資料庫。她不用碰,但你可以在手機上改。

### 欄位

| 欄 | 說明 | 範例 |
|---|---|---|
| `id` | 穩定識別碼,**回饋機制靠它** | `ch09-0012` |
| `chapter` | 章代號 | `ch09` |
| `title` | 短標題 | `抵当権の効力が及ぶ範囲` |
| `question` | 題幹 | |
| `options` | 選項,儲存格內換行分隔 | `○`⏎`×` |
| `answer` | 正解序號,1 起算,複選逗號 | `1` |
| `explanation` | 解說 | |
| `law_refs` | 條文,逗號分隔 | `民法370` |
| `tags` | 論點標籤 | `抵当権, 物上代位` |
| `confidence` | `high` / `mid` / `low` | |
| `status` | `ok` / `flagged` / `fixed` | 回饋迴路用 |

`id` 一旦產生就不要變。她回報的是 id,你改的也是 id 對應的那列。

### 串接

Sheets →「發布到網路」→ 該工作表 → CSV → `fetch()` + PapaParse。前端加 localStorage 快取與 `?refresh=1` 強制重抓。

第二個工作表 `chapters` 放章名對照,前端一併讀,這樣日文章名由資料控制,你不用碰。

發布出的 CSV 網址知道就能存取(即使站台鎖住)。題目內容不敏感,但你知道有這件事。

### 章節架構

```
ch00 序章 ビジネス法務とは            ch09 第9章  債権の担保
ch01 第1章 企業取引・契約にかかわる法務    ch10 第10章 債権の回収
ch02 第2章 企業財産の管理と法務         ch11 第11章 債務者の倒産への対応
ch03 第3章 企業間取引にかかわる法規制     ch12 第12章 法的紛争等の予防と対応
ch04 第4章 消費者との取引にかかわる法規制   ch13 第13章 株式会社の組織と運営
ch05 第5章 情報の管理と活用にかかわる法規制  ch14 第14章 企業と従業員の関係
ch06 第6章 デジタル社会と法律          ch15 第15章 企業活動と地域社会・行政等
ch07 第7章 広告・表示等に関する法規制     ch16 第16章 国際法務(渉外法務)
ch08 第8章 金融・証券業等に関する法規制
```

民法約 1/4、商法/会社法約 1/4。ch01 / ch09 / ch10 / ch13 報酬率最高。

## 4. 回饋迴路(本專案核心)

她發現錯誤的當下,必須能**在三秒內、不離開刷題流程**回報完畢。

### 做法:Google Form + 預填參數

1. 開一個 Google Form,欄位:`question_id`(隱藏預填)、`種類`(選項)、`コメント`(選填)
2. 表單回應自動進 Sheets,你每週看一次
3. 卡片解說區右下放一個小按鈕,開新分頁到預填好 `question_id` 的表單網址

零後端、零認證、零維運。

種類選項(給她的,日文):

```
答えが違うと思う
解説がわかりにくい
条文が違う / 見つからない
誤字・脱字
その他
```

### 三個讓它真的被使用的細節

- **回報後立刻標記。** 該題卡片角落顯示小標記,她再遇到時知道已經報過了,不會重複回報也不會焦慮。用 localStorage 記 id 就好
- **不要跳確認對話框。** 送出後回到原卡片繼續,不要打斷節奏
- **`confidence: low` 的題目視覺上淡淡標一下。** 讓她知道「這題本來就沒把握」,看到怪的地方會更願意回報,而不是懷疑自己

### 你這邊的處理節奏

每週固定時間開回應 Sheet → 把有疑問的題目丟給 AI 複查 → 改 Sheets 對應列 → `status` 改成 `fixed`。改完立刻生效,不用重新部署。

## 6. 技術架構

**不要用框架。** 一個使用者、約 500 筆資料、一個資料來源。

```
bijihou2/
├── index.html
├── app.js
├── style.css
├── config.js        # Sheets CSV URL, Form URL
├── pipeline/        # 不部署
│   ├── raw/
│   ├── convert.md   # AI prompt
│   └── validate.mjs
└── (無 build step)
```

- **題庫**:`fetch` CSV → PapaParse → localStorage 快取
- **進度**:`localStorage`(SM-2 的 interval / ease / due)
- **備份**:「データを書き出す」按鈕。她的複習進度是幾個月的資產,localStorage 會被清掉。提醒她每月存一次

唯一外部相依是 PapaParse,CDN 引入。連 npm 都不用。

## 7. 功能優先序

### MVP

1. 選章節(全部 / ランダム / 今日の復習)
2. 卡片翻面
3. 自評三鍵
4. **回饋按鈕**(這版提前到 MVP,它是核心)
5. 進度 localStorage + 匯出匯入

### 第二輪

- **SM-2 間隔重複** — 三鍵對應 quality 2 / 3 / 5
- **錯題箱** — 自動蒐集「わからない」
- **條文跳轉** — `law_refs` 產生 e-Gov 查詢連結。用搜尋連結而非固定 ID 深連結,比較不會失效
- **低信心優先** — 一鍵列出 `confidence: low`
- **tag 檢索** — 跨章找同一論點(「時効」散在 ch10、ch12)

### 第三輪

- **模擬試験モード** — 隨機 40 題、90 分倒數、結束算分
  (2級為 IBT/CBT,多肢選択式、90 分、約 40 題、70 分合格,年 2 回於 6–7 月與 10–11 月)
- 分章正確率熱圖

## 9. 手機優先

- **三個自評按鈕放螢幕下緣**,單手可達
- **點任何地方翻面**,不要只有小按鈕能點
- **body 至少 17px**。日文漢字在小字級下很難讀
- **加 manifest 與 `apple-mobile-web-app-capable`**,能加入主畫面
- **service worker 離線快取**,通勤地下鐵能刷
- **不要橫向捲動**,長日文題幹要正確斷行
