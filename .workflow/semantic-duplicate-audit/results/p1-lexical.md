## 結論

- `466 x 300 = 139,800` 個跨來源題目配對中，完整正規化後仍是 **0 組逐字相同**；這只代表沒有 identical question，不代表沒有考同一件事。
- 改成「命題單位」比較後，找到 **22 組強候選**（綜合分數 `>= 0.50`，20 個 shikakumondai ID、18 個 dojo ID）及 **51 組寬候選**（`>= 0.40`）。
- 使用者的直覺正確：兩個來源確實大量重複考同一法條、同一要件或同一數字，只是常用同義改寫、正反顛倒或故意替換數字，因此原先只比完整題幹會漏掉。
- 此報告不要求阻擋目前 766 題部署。下一版去重應以「知識點重複」為準，不能只做 exact-string dedupe。

## 可重現方法

資料：`pipeline/output/shikakumondai.json`（466）對 `pipeline/output/shikaku-dojo.json`（300）。

1. Unicode `NFKC`，移除空白、標點、大小寫差異。
2. shikakumondai 題幹按換行拆成 `ア`、`イ` 兩個命題；答案組合選項不納入文字相似度。
3. dojo 的 `○/×` 題以題幹為命題；四選一題則以 `題幹 + 各選項` 為命題，避免只比泛用題幹。
4. 對每組題目取最佳命題配對，計算：
   - `cos`：char TF-IDF cosine，character n-gram `2..5`。
   - `cont`：共同 char trigram / 較短命題 trigram 數。
   - `lcs`：longest common substring / 較短命題長度。
   - `law`：`law_refs` 去除項、款後，法名 + 條號的 Jaccard。
5. 綜合分數：`0.45*cos + 0.20*cont + 0.15*lcs + 0.20*law`。
6. `>=0.50` 只作強候選，人工讀題幹、選項、答案與 explanation，判斷是同命題、正反版本，還是僅同主題。

門檻統計：`>=0.60: 10`、`>=0.50: 22`、`>=0.40: 51`、`>=0.35: 75`、`>=0.30: 117` 組。共同法條根共有 186 組，但單靠同法條誤報很多，不能直接刪題。
