# P3：保守語意去重政策

## 結論

- 現有 `duplicates.json` 為空，只證明沒有「正規化後全文相同」；不代表沒有考相同命題。
- 兩來源確實有多組語意重複：常見形式是近義改寫、肯否反轉、或只替換錯誤數字。
- 本版 766 題不應直接套用模糊相似度刪題。下一版應採「機械產生候選 + 人工確認 + version-controlled allowlist」。除全文／單一敘述完全相同外，不允許相似度分數直接刪題。

## 建議實作於 `pipeline/extract-source.mjs`

1. 將來源一題面拆成個別 `ア／イ／…` 敘述，並由正確選項解析每個敘述的 truth value。題目標題與通用作答句不得參與相似度。
2. 正規化只處理 `NFKC`、空白、標點及固定表記差異（`及び/および`、`又は/または`、`箇月/か月`）。不得移除 `ない`、`不要`、`のみ`、`原則`、`例外`、數字、行為人及適用對象。
3. 法條 key 應保留完整條號，例如 `第24条の4の4`；可另建父條 key，但父條相同只能產生候選，不能判定重複。多法條題也不能因任一附帶引用相同就刪除。
4. 候選產生可用字元 bigram Dice／shorter-side containment：
   - 同完整法條且 Dice `>= 0.45`；或
   - 不依賴法條、Dice `>= 0.60`；或
   - 一個 dojo 敘述可由同一來源題的多個敘述合併完整覆蓋。
5. 自動刪除只保留現有的 exact fingerprint 規則。所有 semantic candidate 必須通過以下證據檢查後，寫入固定 allowlist：相同行為人、客體、法律效果、條件／例外、數字集合，以及 truth polarity 在處理明示否定後一致。
6. Allowlist 建議存成 `{ removed_id, kept_id, reason, evidence_version }`。Pipeline 必須驗證兩個 ID 都存在、同一 `removed_id` 不得重複，並把命中項寫入 `duplicates.json`。來源資料改版後 `evidence_version` 不符即停止移除並回到 review。
7. 驗證必須同時報告：原始題數、exact duplicate、semantic allowlist 移除數、保留數、失效 allowlist、以及每個移除 pair 的題面／答案／法條快照。

核心原則：法條相同只是 topic overlap；只有「答對所需的法律命題相同」才是 semantic duplicate。不同案例、不同例外、不同主體、或新增一個可獨立判斷的條件，均保留。
